# TB App — E2E Coverage Backlog

## ✅ Implemented (41 tests, all green — `npm run test:e2e`)
- **Core/originals:** rest-timer survives refresh + skip-clears; onboarding shows; every screen renders (no crash/blank/ErrorBoundary, zero console errors); direct weight entry + feel/notes → History; rest-timer & theme persist; backup export downloads; malformed import rejected.
- **Dates/phase:** before-countdown; day-0 active; day-41 active; day-42 complete.
- **Today:** lapse-guard Welcome-back (not an unearned Test Day); missed-session nudge + dismissal persists across reload; backup nudge.
- **Session:** in-progress lift logging survives reload; partial "you showed up" (done=false); autosave does NOT clobber Strava enrichment (asserts Dexie row); SE circuit rests only on a full round.
- **Onboarding:** completes → Today & never returns; legacy no-`onboarded` row skips.
- **Progression:** block-complete branches (first-run hold / post-first-run retest / unfinished repeat); force-progress bumps each max by its step (asserts bumpKg deltas).
- **Maxes:** BB "nothing to do"; Operator wave table; 60kg-ceiling ⚠ flag.
- **Settings:** load-basis confirm — cancel is a no-op / accept persists.
- **Backup:** rejects missing-tables / newer-version / no-app-row; a valid backup restores after confirmation.
- **History:** empty state; delete-from-list removes + persists.
- **Strava (mocked `/api/strava/*`):** run auto-ticks the matching day on open; lift write-back PUTs name+description (breakdown); sync-failure banner; revoked-token reconnect banner.

## ⏭ Deliberately left (better as unit tests or need extra scaffolding)
- **Backup snapshot-rollback on a mid-import write failure (#9)** — needs an injected failure hook; hard to trigger black-box.
- **Exact load-math** (per-week working weights, TM-vs-1RM numbers) and **streak tolerance counting** — pure functions; better as a small **Vitest unit suite** than E2E.
- **Clock-dependent:** auto-complete today's rest after 23:55 — needs `page.clock`.
- Device-only (see §4): real notifications, audio-through-lock, live Strava OAuth, PWA install.

## 1. Summary

This backlog enumerates **107 test-worthy scenarios** across 12 subsystems, on top of the **9 already-covered** tests. All claims below were verified against the real source (`Today.tsx`, `stravaSync.ts`, `stats.ts`, `backup.ts`, `autocomplete.ts`, `progression.ts`, `db.ts`).

**Coverage picture:**

- **Solid where it counts** — the highest-risk logic is now enumerated concretely: the phase-boundary date math (`resolvePosition` day-0/day-41/day-42 flips), the lapse guards that stop an unearned Test Day, the Operator first-run/retest/force-progress ladder, Strava auto-tick guards + write-back idempotency, autosave-doesn't-clobber-enrichment, and the backup snapshot/rollback + token-stripping guarantees. These are the paths most likely to silently corrupt Josh's real data or push him into the wrong week.
- **Thin / needs a harness affordance** — anything needing a **faked wall clock** (today's-rest auto-complete after 23:55; the ≤3-day streak tolerance is cleaner to drive via injected dates than clock-mocking). And the **deliberate render crash** for ErrorBoundary needs the fixture's console-error auto-fail suppressed for that one test.
- **Partial (needs `page.route` mocking)** — the entire Strava subsystem: OAuth callback, throttled auto-sync, run/lift write-back, error-banner classification. Fully automatable once `/api/strava/*` is mocked; no live Strava needed because state lives in IndexedDB.
- **Genuinely device-only** — real push notifications, audio-through-lock rest chimes, live Strava OAuth redirect, and PWA install/update — see §4.

**Automatable split:** ~86 `yes` · ~20 `partial` (Strava/clock mock) · a handful `device-only`.

## 2. Recommended build order (highest value first)

1. **Day-0 → active, day-41 active, day-42 complete** (`resolvePosition` boundary trio) — the off-by-one that decides which week Josh trains.
2. **Complete-but-lapsed → "Welcome back / Resume from week N"** (not an unearned Test Day) — the guard that protects a real lay-off.
3. **Autosave must NOT clobber Strava duration/HR/distance/stravaId on an enriched run** — core "don't lose data" guarantee; assert the Dexie row.
4. **In-progress lift logging survives a full reload** (index-based `[exIdx][setIdx]` hydration) — the everyday autosave path.
5. **Tick all sets → done=true; partial → "you showed up" done=false** — the two completion states, DOM + row.
6. **Rest timer: starts on tick, +30s extends, end-time persists across reload** — already partially covered for survive/skip; this adds the extend + start-on-tick gate.
7. **SE circuit: rest fires only when a ROUND completes, not per move** — round-by-round correctness.
8. **Import rejects missing-tables / newer-version / no-app-row backups; data intact** — three guard messages, DB untouched.
9. **Snapshot rollback restores prior data when the import write throws mid-way** — the safety net itself (needs a poisoned session row or a mocked `bulkPut`).
10. **Export strips Strava tokens; restore re-injects the on-device connection** — token never lands in a file Josh emails himself.
11. **Missed-session nudge + its dismissal persists across reload (keyed to the date)** — localStorage `tb-dismiss-missed`.
12. **Operator block-complete branches: first-run hold vs post-first-run retest vs not-completed repeat vs no-maxes** — the four-way progression fork.
13. **forceProgress bumps each max by its step + advances block; retest confirm clears progression & routes to Maxes** — mutating engine paths, assert bumpKg deltas.
14. **Maxes: test weight+reps saves + populates wave table; 60kg ceiling ⚠ clamp; TM-vs-1RM rescale** — the calculator's load-bearing math.
15. **Strava run auto-ticks the matching run/HIC day; NOT a lift day / inactive day / already-synced day** (partial, mock activities).
16. **Strava lift write-back PUTs name+description with 1RM/volume; idempotent no-re-PUT when already linked+named** (partial).
17. **Sync failure → "Couldn't reach Strava"; revoked token → "Strava needs reconnecting" (reconnect beats sync-error)** (partial).
18. **Onboarding completes → lands on Today reactively; never re-appears after reload; legacy no-`onboarded` row skips it.**
19. **Load-basis / phase-switch confirms: cancel is a no-op, accept persists & rescales** (Settings, dialog-gated).
20. **History delete-from-list confirm + persists across reload; empty-history EmptyState early-return.**

## 4. Device-only (can't be automated headlessly)
