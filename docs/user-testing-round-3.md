# TB App — Critique Round 3

## Overall health
The app is in genuinely good shape: the training program is book-faithful, the local-first model is clean, and the highest-friction interaction (the per-set Done toggle) is already sized and celebrated correctly. Round 3 did not surface a broken program — it surfaced a cluster of **data-durability risks** (iOS can silently evict the only copy of Josh's data, and both the import and the service-worker paths can destroy or brick it) and a set of **6am-adherence gaps** where the app's motivational and logging machinery quietly fails the exact groggy, low-energy morning it exists to serve. The most striking pattern is *plumbing that's 90% built but inert*: `feel`, `notes`, `operatorFirstRunDone`, and the bump-aware Maxes table are all wired into the DB but never read, set, or applied correctly — cheap wins hiding in code you already wrote. Several correctness bugs (autosave clobbering Strava enrichment, the phase-complete door bypassing lapse handling, `operatorFirstRunDone` never flipping true) would cause the app to quietly mislead a user who *trusts it to drive*. Fix the data-loss tier first, then the inert plumbing, then the morning-cue and reward gaps.

## Top priorities

1. **Make IndexedDB persistent + nudge backups** — iOS can evict best-effort storage after ~7 days idle, wiping his only copy of maxes/history; nothing prompts him to export. Add `navigator.storage.persist()` and a `lastBackupAt`-driven Today banner. **(S)** — `main.tsx`/`db.ts`, `Settings.tsx`, `Today.tsx`
2. **Harden the import path (validate + confirm + snapshot)** — `importBackup` clears all tables before validating and fires with no confirmation, so one fat-fingered restore during a phone switch destroys everything. Validate shape before any `clear()`, add a `window.confirm`, snapshot-and-rollback on failure. **(M)** — `db.ts:88-97`, `Settings.tsx:65-75`
3. **Surface Strava sync failures instead of swallowing them** — `App.tsx:36` is an empty `catch`; a revoked token or dead 6am signal means his runs silently stop appearing forever with zero signal why. Persist a sync-error/reconnect flag and show a Today banner. **(S)** — `App.tsx:29-36`, `strava.ts:84`
4. **Fix the autosave→Strava clobber** — the autosave effect keeps a stale `logged` closure and re-writes it on the next set tick, overwriting HR/duration that `syncStrava()` just merged in on the same day. Re-read the row inside the save and merge. **(S)** — `Session.tsx:145-178`
5. **Control the service-worker update swap** — `skipWaiting` + `clientsClaim` + `cleanupOutdatedCaches` can evict old chunks mid-session and chunk-load-error a live 6am session. Adopt the `registerSW`/`onNeedRefresh` "tap to reload" pill (also gives him the version indicator he wants). **(M)** — `vite.config.ts`, `dist/sw.js`, `main.tsx`
6. **Ship the dead journal (`feel` + `notes`) and fix `operatorFirstRunDone`** — two cheap, high-value inert-plumbing fixes: render the feel/notes inputs that autosave already supports, and flip `operatorFirstRunDone` true in `retest()`/`forceProgress()` so a seasoned lifter isn't told he's on his "first 12 weeks — hold the weights" forever. **(S)** — `Session.tsx`, `History.tsx`, `Today.tsx:105/116`
7. **Guard the phase-complete → lapse door** — a ~3-week lapse near the end of Base Building rolls the calendar past week 8 and drops Josh on the "do your Test Day" celebration, pushing him to test 1RMs he never built. Hoist the lapse check above the `status:'complete'` branch. **(M)** — `Today.tsx:67-201`, `program.ts:297-298`
8. **Reliable rest-timer end cue + bigger steppers** — the buzz lives in a throttleable `setInterval` and never fires through a locked screen; the ±weight/rep steppers are 32px in a tight cluster. Schedule a WebAudio beep at `restEnd` and bump `STEP` to 44px. Both hit his literal dark-6am, one-handed use. **(M/S)** — `Session.tsx:131-142`, `Session.tsx:47-48`

## Themes

**Data durability is the real risk surface.** The program logic is sound; the danger is that the *only* copy of Josh's data lives in a best-effort IndexedDB bucket with a manual-only backup, a destructive un-validated import, an un-versioned export, plaintext Strava tokens in the backup file, and a service worker that can brick a live session. None of these bite often, but each is a total-loss or hard-to-recover event, and the mitigations (persist, validate, confirm, snapshot, error boundary) are almost all small. This tier should ship before any feature work.

**Inert plumbing — code you already wrote that does nothing.** `feel` and `notes` are typed, hydrated, and autosaved but have no input UI and no read-back. `operatorFirstRunDone` is only ever written `false`. The Maxes working-weights table omits `bumpKg` so it disagrees with the header directly above it. These are the highest ROI in the whole report: the hard part is done, they just need wiring — and each currently *misleads* Josh (a fictional journal, a permanent "first run", two different weights for the same lift).

**The 6am cue-and-reward loop has holes exactly where an ADHD user needs it.** There's no morning trigger at all — the whole loop depends on Josh remembering to open the app unprompted, his weakest link. Once inside, a partial or held-block session earns nothing (flat strength chart, no PR possible for 12 weeks, partials don't count toward the streak), rest days offer no micro-action, and the streak zeroes on an ordinary 4-day life gap with no all-time record kept. The reward system pays out on perfection while the copy preaches "showing up beats skipping" — a mismatch that quietly punishes the exact behaviour the app is trying to build.

**Correctness bugs that mislead a user who trusts the app to drive.** Beyond the inert plumbing, several live-logic paths steer Josh wrong: the phase-complete door bypasses lapse handling and pushes an unearned Test Day; `realign()` silently re-does a completed week; autosave clobbers Strava enrichment; and the block-complete flow re-arms the 12-week hold after every retest. Because Josh is explicitly *not* second-guessing the app, these are more dangerous than for a skeptical user.

**Touch, legibility, and cue reliability in the dark.** His stated context — ~6am, in the dark, one-handed, cold hands — makes several low-severity items matter more than their tags suggest: 32px steppers in a tight cluster, a near-invisible unchecked tick (~1.25:1), 9px unit labels, `maximum-scale=1` blocking pinch-zoom, a PWA status-bar stuck light, and a rest-timer cue that can't survive a locked screen. Cheap fixes, real daily friction.

**The Strava proxy is an open relay.** All three Cloudflare Functions (`token`, `activities`, `update`) are unauthenticated and forward caller-supplied tokens to Strava under Josh's app identity. No secret leaks, so the realistic harm is quota/relay abuse that could get his Strava app flagged — but a single shared-secret `_middleware.ts` gate closes all three at once. Worth doing cheaply.
